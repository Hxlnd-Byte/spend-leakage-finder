# Spend Leakage Finder

**A small, honest example of AI saving a company money, running entirely on one workstation.**

A CFO asks two questions about AI: *Did we use it to solve a real problem?* and *Did it save us money?*
This project answers both. AI reads supplier contracts and invoices. Ordinary code checks them against each other.
The money sits in the gap between what the contract says and what the supplier billed.

> Everything here is fictional. Halden Group is a made-up company of 1,200 people. The suppliers, contracts and invoices are generated by a script, with every mistake planted on purpose and written down in an answer key.

## What it finds

| Leak | Plain meaning |
|---|---|
| Duplicate | The same bill paid twice |
| Rate over contract | A price rise bigger than the contract allows |
| Billed after expiry | Invoices for a contract that has ended |
| Quantity over maximum | More seats or devices billed than the contract allows |
| Charge not in contract | A fuel, delivery or admin surcharge nobody agreed |
| Arithmetic error | An invoice that does not add up |

It also builds a **renewal watch-list**: contracts whose "tell us you are leaving" deadline is close, or has already passed. That is avoided cost, not recovered cash, so it is reported separately.

## The one design rule

**The AI reads. The code calculates and checks.**

Language models are good at reading messy documents and poor at arithmetic and date maths. So the AI only copies facts (dates, rates, notice periods) into a fixed form. Plain code works out end dates, notice deadlines, allowed prices and differences. You can read, argue with and change every rule in `03_reconcile.py`.

## Quick start (Windows)

Full step-by-step guide: [docs/SETUP_WINDOWS.md](docs/SETUP_WINDOWS.md)

```powershell
git clone https://github.com/<your-name>/spend-leakage-finder
cd spend-leakage-finder
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
ollama pull qwen2.5:7b
python 01_generate_data.py
python run_all.py --limit 5        # try 5 documents of each kind first
python run_all.py                  # the full run
```

No AI installed yet? `python run_all.py --extractor mock` tests the plumbing with a stand-in reader. Those results are labelled **MOCK** and are not a measurement.

## What is in the box

| File | Job |
|---|---|
| `01_generate_data.py` | Builds 30 contracts, 166 invoices and the answer key (fixed seed, same every time) |
| `02_extract.py` | The AI step: reads each PDF with a local model and fills in a fixed form |
| `03_reconcile.py` | The rules: matches invoices to contracts and flags leakage and renewals |
| `04_score_and_report.py` | Marks the tool against the answer key, writes the report and charts |
| `05_value_model.py` | Low / base / high cost-benefit model from `assumptions.toml` |
| `run_all.py` | Runs the steps in order |
| `tests/` | Tests that need no AI |
| `docs/` | Setup guide, why each tool was chosen, how to test and read the results |

## Where the numbers come from

The business case cites published research on contract value lost, duplicate payments and missed renewals. Several of those figures come from vendors who sell related products, so treat them as a range, not a promise. `assumptions.toml` labels every input as **benchmark** or **assumption**; replace the assumptions with your own company's figures.

## Honest limits

- The test set is built with a deliberately high error rate (about one invoice in six). A real company will have far fewer.
- Savings are **modelled**. The only measured quantity is how many planted mistakes the tool caught.
- The documents are clean, text-based PDFs. Scanned paper needs an extra reading step (OCR).
- One misread contract fact can cause many false alarms, because every invoice for that supplier is then judged against the wrong number. Keep a person in the loop: the tool produces a **review list**, not automatic payments or disputes.
- It does not talk to suppliers, change payments or touch any system. It only reads files and writes reports.

## Sovereignty

All documents and the model stay on your machine. Nothing is sent to a cloud service. Contracts and invoices are among the most commercially sensitive documents a company holds, which is a good reason to start with local processing.
